# 09｜Narrative → Visual Decision Tree

这是一条用于实际项目决策的最短路径。

## 1. Narrative Core
先问：角色最怕失去什么？不要先问配色或媒介。

自由/束缚优先考虑Space与Direction；亲密/疏离考虑Distance与Edge；身份自主考虑Shape、Medium或Time；被看见考虑Contrast、Focus与Framing；记忆考虑Layer、Texture与Focus；秩序考虑Grid与Repetition；失控考虑Rhythm与Density。

## 2. Assign Primary Variable
只选一个Primary。再选2–3个Secondary。其余变量默认保持克制。

## 3. Define Identity Anchor
问：如果颜色、灯光、材质、世界全部变化，最低限度保留什么仍然能认出角色？至少建立Shape、Value、Motion等多个识别通道。

## 4. Define World Baseline
先定义世界默认怎么工作，再判断角色在哪些维度Harmonize、Amplify、Resist、Destabilize或Rewrite世界。

## 5. Build State Machine
Baseline → Pressure → Crisis → Decision → Agency → Resolution。每个Transition必须有Narrative Trigger。

## 6. Define Failure
身份危机不是“视觉变坏”，而是角色专属规则停止工作：Range Collapse、Boundary Logic Failure、Forced Uniformity、Focus Logic Collapse等。

## 7. Define Agency
Agency不是更亮、更大、更酷，而是Variable Ownership Transfer：角色开始控制此前由世界、他人或系统控制的核心变量。

## 8. Build Sequence Score
为每个Beat记录Lead Variable、Support、Silent、Intensity、Organization、Agency、Information Load与Camera关系。高潮优先寻找Ownership Shift，而非Maximum Noise。

## 9. Add Color
依次判断Color Function → Ownership → Territory → Boundary → Migration → Saturation/Value → Timing → POV → Residue。颜色必须有工作，不只是漂亮。

## 10. Select Medium
最后才选择水彩、印刷、CG、墨、Marker等。选择依据是Medium Behavior是否支持Primary Variable，而不是标签是否流行。

## 11. Constraint Test
禁止原角色、原世界、原色板、原媒介和标志性效果。如果Narrative Verb、Hierarchy和Character–World Relation仍成立，说明理解的是机制。

## 12. QA
最终问：第一读取是什么？Primary Variable是否承担故事？Anchor是否稳定？是否存在无功能特效？是否消耗了过多Visual Reserve？Break是否有触发条件？Resolution是否形成Baseline B？

## Master Formula

Narrative → Character Interpretation → Primary Variable → Identity Anchor → World Grammar → State → Visual Mechanism → Sequence Curve → Ownership Transfer → Resolution → Production QA
