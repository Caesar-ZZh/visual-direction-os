# 4000-Frame Evidence Coverage Matrix

## Purpose

The research target is now an approximately **4,000-frame high-coverage evidence corpus**, not a mechanical pass over every available screenshot.

A frame counts toward the 4,000 only when it has actually been visually opened and receives at least L1 distillation. The selection policy must collectively cover **every existing Visual Direction chapter**, all major characters/worlds, major rendering families, camera/composition mechanisms, sequence behaviors, counterexamples, and direct generative/QA implications.

The 4,000 frames are a multi-label corpus: one frame may support several chapters. Chapter target counts below are therefore **coverage floors**, not mutually exclusive quotas and do not need to sum to 4,000.

## Selection priority

```text
Coverage gap
→ representative frame
→ transition/change-point frame
→ counterexample
→ sequence continuity support
→ deep diagnostic
```

Near-duplicates are no longer automatically selected simply because they exist in the source corpus. They enter the 4,000 only when they contribute temporal evidence, micro-performance evidence, held-channel evidence, or a needed counterexample.

## Batch rules under the 4,000-frame strategy

Each batch must answer four questions:

1. **What existing GitHub chapter(s) does this evidence strengthen?**
2. **What prior assumption does it validate, narrow, revise, or contradict?**
3. **What production / Skill parameter follows from the evidence?**
4. **What coverage gap should influence later sampling?**

Adaptive batch size:

```text
extreme / high change     → 24–36
normal narrative segment → ~48
low-change held sequence → 48–60, but only if temporal evidence is useful
```

## Evidence levels

- **L1** — every selected frame: actually opened + minimum structural annotation.
- **L2** — change point / representative / counterexample with mechanism-level analysis.
- **L3 / Deep** — diagnostic frame or short sequence used to revise theory, workflow, prompt schema or QA.

The 4,000-frame target should contain a high density of L2/L3 evidence rather than thousands of redundant near-duplicates.

## Promotion policy into the main chapters

Evidence-calibrated batch files may contain provisional findings immediately. A mechanism should be promoted into the stable main methodology when:

1. it has support across independent shots/scenes or a clearly defined narrow scope;
2. counterexamples have been actively searched;
3. the mechanism changes an actual production decision;
4. the rule survives generative/constraint reconstruction;
5. its scope is explicit: character, world, state, sequence or whole-film.

Therefore the 4,000-frame corpus is not only a reference archive. It is the evidence engine that continuously rewrites the GitHub methodology.
